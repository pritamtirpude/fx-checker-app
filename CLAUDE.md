## Project Overview

FX Checker is a currency exchange rate checker built on **TanStack Start** (React 19 + file-based TanStack Router + TanStack Query + Nitro SSR server). It fetches live, historical, and single-pair rates from the [Frankfurter](https://frankfurter.dev) API and renders a rate-converter UI with a live ticker, currency picker, and historical rate chart tabs.

## Commands

```bash
npm run dev              # Start dev server at http://localhost:3000
npm run build             # Production build (outputs .output/, Nitro server bundle)
npm run preview           # Preview the production build locally
npm run generate-routes   # Regenerate src/routeTree.gen.ts (tsr generate) — usually automatic on save in dev
npm run lint               # ESLint (@tanstack/eslint-config)
npm run format             # Prettier --write + eslint --fix
npm run check               # Prettier --check only (no writes)
npm run test                # Run all tests with Vitest
```

- There is no per-file "run a single test" script defined; use Vitest's own filtering directly, e.g. `npx vitest run path/to/file.test.tsx` or `npx vitest run -t "test name"`.
- **No test files exist in the repo yet** even though Vitest, Testing Library, and jsdom are installed as devDependencies — there is also no `vitest.config.ts`, so a new test setup (environment: jsdom, testing-library matchers, etc.) will need to be wired up before `npm run test` does anything useful.
- Installing dependencies requires network access to a private scoped registry (see **Environment variables** below) for the `@motionplus/core` package — `npm install` will fail without `MOTION_TOKEN` set.

## Architecture

### Path aliases

Source imports use `@/*` → `src/*` (defined in `tsconfig.json`). Ignore the `#/*` entry in `package.json`'s `imports` field — it's unused; every file in the codebase imports via `@/`.

### Routing & data-loading pattern

- File-based routes live in `src/routes/`; `src/routeTree.gen.ts` is auto-generated by the TanStack Router CLI (`tsr generate`) — **never hand-edit it**.
- `src/routes/__root.tsx` defines the HTML shell, wraps everything in `ThemeProvider` (see below), and mounts `TanStackDevtools` (Router + Query panels) bottom-right.
- `src/routes/index.tsx` (`/`) is the only real route. It:
  - Declares `validateSearch` for the `base`/`quote` URL search params (defaults `USD`/`EUR`) — **these search params are the source of truth for which currency pair is selected**, not component state.
  - Uses a route `loader` that calls `context.queryClient.ensureQueryData(...)` in parallel for every query the page needs (live rates, yesterday's rates, currencies list, single-rate conversion, history rates) so data is present before/during SSR render.
  - Reads the *current* period directly from the Zustand store (`useCurrencyStore.getState()`) inside the loader — the loader deliberately depends on both the URL (`base`/`quote`) and store state (`period`) to prefetch correctly.
- Router setup (`src/router.tsx`) wires `@tanstack/react-router-ssr-query` so the router-managed `QueryClient` (created in `src/integrations/tanstack-query/root-provider.tsx`) hydrates correctly between server and client.

### Dual state model: URL params vs. Zustand store

This is the trickiest part of the codebase to get right when touching currency-selection logic:

- **URL search params (`base`, `quote`)** hold the selected currency **ISO codes** and drive query keys/loader prefetching (`src/routes/index.tsx`, `CheckRate.tsx`, `HistoryHeader.tsx`).
- **`useCurrencyStore` (`src/store/store.ts`, Zustand)** holds the full `CurrencyOption` objects (`{ flag, code, name }`) for `send`/`receive` (needed for rendering flags/names in the dropdown), plus UI-only state: `amount` and the selected history `period`.
- Selecting a currency in `CurrencyDropdown.tsx` updates *both*: it calls the store setter (`setSend`/`setReceive`) **and** calls `navigate({ to: '.', search: (prev) => ({ ...prev, [base|quote]: code }) })` to keep the URL in sync. Swapping currencies (`CheckRate.tsx`'s `handleSwap`) does the same in both directions.
- On first load, `CurrencyDropdown` seeds the store from the URL's default code once the currencies list has loaded (see its `useEffect` keyed on `currencies.length`).
- When adding new currency-aware features, keep both in sync the same way — reading only one of the two will produce stale UI or broken prefetching.

### API / query layer (`src/api/`)

One file per resource, each following the same shape:

1. A `createServerFn` (TanStack Start) that does the actual `fetch` against `${process.env.BASE_URL}` (Frankfurter-style FX API) and returns typed JSON (`Currency`, `Rate`, `Rates` from `src/types/index.ts`).
2. An exported `fetch<Resource>Options(...)` function returning TanStack Query `queryOptions` (query key, query fn calling the server function, and any `enabled`/`staleTime`/`refetchInterval`).

Files:
- `currencies.ts` — full currency list (`['currencies']`).
- `liverates.ts` — live USD-based rates for ~55 quotes, polled every 60s (`staleTime`/`refetchInterval: 60_000`), plus a matching "yesterday" snapshot cached for 24h, used together by `useRateChanges` to compute live deltas.
- `singlecurrency.ts` — single base→quote rate; query fn multiplies `rate * amount` client-side into a `converted` field (query key includes `amount`, so every amount change is a new cache entry).
- `historyrates.ts` — base→quote series over a `Period` (`'1D' | '1W' | '1M' | '3M' | '1Y' | '5Y'`), converting the period to a `from`/`to` date range via `date-fns` `sub`/`format` before calling the server fn.

When adding a new endpoint, follow this same server-fn + `queryOptions` factory pattern rather than calling `fetch` directly from components.

### Currency/flag mapping

`src/utils/currency.ts` maintains a hardcoded ISO-4217 → ISO-3166 alpha-2 map (`CURRENCY_FLAG_MAP`) used to resolve flag images under `public/assets/images/flags/*.webp`. `getCurrencyOptions()` **filters out any currency not in this map** — so the API's currency list and the app's usable currency list are not the same set. Adding support for a new currency requires both a flag asset and a map entry here.

### Styling

- Tailwind CSS v4, CSS-first config — there is **no `tailwind.config.js`**; all design tokens (colors, type scale, letter-spacing/line-height presets) are defined via `@theme` in `src/styles.css` using the `fx-*` naming convention (`fx-neutral-*`, `fx-lime-*`, `fx-green-500`, `fx-red-500`) and `text-preset-1`…`text-preset-6` typography presets. Use these tokens instead of raw Tailwind palette classes/arbitrary values to stay consistent with the design system.
- `cn()` (`src/utils/index.ts`, `clsx` + `tailwind-merge`) is the standard way to conditionally compose class names.
- Dark/light/system theme is handled by `src/context/ThemeProvider.tsx`, which injects an inline script via `ScriptOnce` (in `__root.tsx`) to set the `dark`/`light` class before hydration and avoid a flash of unstyled theme.

### Animation

Two motion libraries are in play: `motion/react` (tab-indicator layout animations in `Tabs.tsx`/`HistoryPeriodTabs.tsx` via shared `layoutId`s) and `motion-plus/react` (`Ticker` component powering the scrolling `LiveTicker`). `motion-plus` ships from a private scoped registry — see below.

### Environment variables

Defined in `.env` (present in repo, not committed patterns aside — check `.gitignore` before adding secrets):
- `BASE_URL` — Frankfurter FX API base (`https://api.frankfurter.dev/v2`), read via `process.env.BASE_URL` inside server functions.
- `MOTION_TOKEN` — auth token for the `@motionplus` private npm registry, referenced by `.npmrc` (`@motionplus:registry=...` / `_authToken=${MOTION_TOKEN}`). Required for `npm install` to resolve `motion-plus`.

### Custom `Tabs` component

`src/components/Tabs.tsx` is a bespoke tabs implementation (not from a library): `Tabs` takes `Tab` children, tracks active tab via internal state + event delegation (`onClickCapture` + `data-tab-title`), and optionally portals the active panel's content into a `target` ref via `createPortal` instead of rendering inline. Used in `routes/index.tsx` for the history/compare/favorites/log sections.
